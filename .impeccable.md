# Design Principles & Vocabulary — MySiteAgent

## Core Philosophy

MySiteAgent produces content for professional Italian websites. All generated content must be clear, purposeful, and consistent with the established design system. No element exists without a reason.

## Design Token System

All visual values — colors, spacing, typography, border-radius — come exclusively from `src/styles/tokens.css`. This file is the single source of truth for all design decisions.

### Token Vocabulary

**Colors**
- `--color-primary`: Main brand color. Use for primary actions (buttons, links, focus rings).
- `--color-secondary`: Supporting brand color. Use for secondary UI elements.
- `--color-background`: Page background. Always white in light mode.
- `--color-foreground`: Primary text color. Dark, high-contrast.
- `--color-muted`: Secondary text, captions, placeholders. Lower contrast than foreground.
- `--color-accent`: Highlight and interactive states. Use sparingly.
- `--color-surface`: Slightly off-white surface for cards, sections, panels.
- `--color-border`: Subtle border color for dividers and input outlines.
- `--color-error`: Error states, destructive actions.
- `--color-success`: Confirmation states, successful operations.

**Spacing**
Spacing follows a consistent scale: `xs` (4px equiv) → `sm` (8px) → `md` (16px) → `lg` (24px) → `xl` (32px) → `2xl` (48px) → `3xl` (64px).
- Use `xs`/`sm` for tight internal padding.
- Use `md` for standard section padding and gaps.
- Use `lg`/`xl` for component-level whitespace.
- Use `2xl`/`3xl` for page-level sections.

**Typography**
- Font sizes: `xs` → `sm` → `base` → `lg` → `xl` → `2xl` → `3xl` → `4xl`
- Font weights: `normal` (400) → `medium` (500) → `semibold` (600) → `bold` (700)
- Body text: `text-base` with `leading-relaxed`
- Headings: `text-3xl` or `text-4xl` with `font-bold` and `leading-tight`
- Captions/meta: `text-sm` with `text-muted`

**Border Radius**
- Inputs, small elements: `rounded-md`
- Cards, panels: `rounded-lg`
- Buttons: `rounded-md`
- Pills/tags: `rounded-full`

## Component Conventions

Every Astro component must:
1. Have a corresponding spec file at `src/components/specs/[Name].md`
2. Use only Tailwind classes that map to token variables
3. Declare TypeScript props with an `interface Props` block
4. Never contain hardcoded colors, pixel values, or inline styles

## Content Language

- All UI text visible to end users: **Italian**
- Error messages: Italian, friendly and non-technical
- Success messages: Italian, concise and affirming
- Code, variable names, component names: English
- Branch names: English, kebab-case

## Forbidden Patterns

The following patterns are NEVER acceptable in generated code:
- Hardcoded hex colors (`#3B82F6`), `rgb()`, `rgba()`, `hsl()`
- Hardcoded pixel values (`15px`, `24px`)
- `eval()`, `new Function()`, `innerHTML =`
- Inline event handlers (`onclick=`, `onload=`)
- `fetch()` to external URLs
- Dynamic `import()` from external URLs
- Placeholder text (Lorem ipsum, [TODO], PLACEHOLDER)
- Truncated content ending with `...`

## Tone of Voice

Content for end users should be:
- **Chiaro**: Easy to understand, no technical jargon
- **Diretto**: Get to the point without filler phrases
- **Cordiale**: Warm but professional
- **Preciso**: Accurate, no vague promises
